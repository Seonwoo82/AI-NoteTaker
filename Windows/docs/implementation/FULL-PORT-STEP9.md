## 회의록의 원문과 문서 바이트

`MeetingNotes.Original`은 생성에 사용한 전사문·전사 모델·오디오 버전/해시와 필요한 화자 전사를 함께 보관한다. 보완과 다시 정리도 이 출처를 사용한다. 예전 회의록은 저장된 `TranscriptHash`와 정확히 일치하는 현재 전사 또는 `TranscriptHistory` 파일에서만 출처를 복구한다. 일치하는 자료가 없으면 기존 회의록을 유지하며 원문 복구/회의록 재생성이 필요하다. 최신 전사문을 과거 회의록의 원문으로 임의 연결하지 않는다.

`SyncDocumentStore`는 내려받은 notes/intelligence 원본 바이트와 descriptor, 로컬 파일의 해시를 함께 저장한다. 로컬 파일이 그대로면 JSON을 다시 직렬화하지 않고 원본을 재사용한다. SHA-256·크기·문서 ID·오디오 버전·생성 시각을 확인한다. 원문 전사는 회의록 문서에 포함하지만 PC별 오디오 해시·모델 설치 경로는 동기화 DTO에 포함하지 않는다. 다른 기기의 회의록이 들어와도 별도로 갱신된 로컬 전사 캐시는 유지하며, 회의록은 자체 원문을 가진다.

notes는 `(generatedAtMillis, revision)`, intelligence는 `(modifiedAt, mutationID)`로 비교한다. 분석 문서의 SHA가 더 크더라도 수정 ID가 작은 문서로 바꾸지 않는 경우를 실제 Worker에서 검증했다. 다운로드 중 로컬 문서가 바뀌면 덮어쓰지 않고 다음 실행에서 다시 비교한다.

## 수정 이력·프로필·설정

- 수정 이력 페이지는 순서/중복/진행 여부를 확인하고, 수신함과 서버 cursor를 같은 파일 트랜잭션으로 저장한다. 해당 녹음을 아직 받지 못했거나 녹음 중이면 수신함에 남긴다. 이후 메타데이터와 오디오를 받으면 로컬 이력에 병합한다. 로컬의 같은 수정 ID가 다른 값을 갖고 있으면 중단한다. 업로드 acknowledgement만으로 전체 수신 cursor를 앞당기지 않는다.
- 텍스트 프로필은 수정 시각/ID를 유지해 병합한다. 비어 있는 새 PC의 기본 프로필로 기존 서버 프로필을 지우지 않는다. 목소리 파일·임베딩은 이 경로에서 읽거나 전송하지 않는다.
- 공유 AI 설정에는 클라우드 모델 ID, 별도 보완 모델, 출력 언어, 자동 생성, 전사 정리 설정만 포함한다. 로컬/클라우드 엔진 선택, Ollama 주소·로컬 모델, GPU 선택, 음성 언어 등 PC별 실행 설정은 보존한다. API 키와 공유 토큰의 보호된 값도 그대로 유지한다.
- 새 기본 설정은 기존 서버 설정을 덮어쓰지 않는다. 공유 항목을 편집하면 수정 시각/ID가 저장된다. 이전 설정 파일은 실제 파일 수정 시각으로 옮긴다. 서버별 acknowledgement와 별도 기기 ID를 사용하고, 기기별 API 키 보유 여부만 전달한다. 읽을 수 없는 키의 보유 여부는 unknown으로 전송한다.
- 전체 실행기의 대기 기록은 문서/수정 이력/프로필/설정도 포함한다. 오디오 버전이 바뀌거나 삭제된 경우 이전 버전의 대기 항목을 정리하며, 원문/문서 자체와 기존 이력은 보관한다.

한글과 `<` 같은 문자가 로컬 JSON에서 escape되면 원래 UTF-8 전송 본문보다 커질 수 있다. 전송 한도(notes 2 MiB, intelligence 4 MiB, profile 60 KiB)를 유지하고 로컬 저장 파일 크기와 분리했다. 서버 한도 이내의 큰 한글 문서를 저장한 뒤 다시 읽는 검증이 통과했다. 모델 응답의 4 MiB 제한은 유지한다.

## 검증 결과

전체 테스트 실행은 **193 통과, 장치 사용 테스트 5개 건너뜀**이다. 이후 추가한 분석 문서 동률 충돌 테스트 1개도 통과했다. Windows 빌드는 경고/오류 0개다.

`SyncDocumentsTests`에서 실제 Worker 핸들러 + loopback HTTP + SQLite와 두 Windows 라이브러리로 확인한 내용:

1. 회의록·분석·수동 화자명/업무 상태·프로필·모델 설정 왕복
2. 로컬 API 키/공유 토큰/목소리/실행 엔진 설정 보존 및 실제 JSON 요청 본문에 비밀 값 없음
3. Apple 형식의 JSON 공백과 소수점 날짜까지 원본 바이트 유지, 로컬 전사문 변경 이후에도 같은 서버 revision 유지
4. 회의록 업로드 실패 후 영속 대기 기록으로 재시도, 누락된 녹음의 수정 이력을 수신함에 보관하고 재시작 후 적용
5. 문서/프로필/설정 다운로드 중 로컬 편집 보존, 재시도 반영
6. 과거 회의록에 최신 원문을 잘못 연결하지 않음, 해시가 일치하는 이력에서만 복구
7. 큰 한글/escape 문서의 저장/재로드와 수정 시각이 같은 분석 문서의 mutation ID 우선 비교

`--smoke-notes Windows/artifacts/sync-step9-notes-ui <model-root>`도 통과했다. 실제 로컬 Qwen 3.5 4B로 정리/보완하고, WPF에서 미리보기·버리기·취소·동시 변경 보호·적용·목차 이동·모델 검색/키 삭제를 확인했다. 전사문을 교체한 fixture에서도 생성 당시 정리본을 구분해 표시하며, `cleanup-original-source.png`를 직접 확인했다. 작성한 문장과 무음 WAV만 사용했다. 실제 회의 정확도 검증을 뜻하지 않는다. 익명 모델 목록 조회는 전사/요약 유료 API 호출과 별개다.

R2는 여전히 로컬 파일 저장소 대역이며 실제 Cloudflare 배포 및 실제 Apple 기기의 왕복 증거는 아니다.
