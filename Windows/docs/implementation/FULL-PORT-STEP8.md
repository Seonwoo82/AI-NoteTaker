# 녹음 라이브러리 동기화 실행기와 중단 복구

후속 회의 자료/프로필/AI 설정 병합은 [단계 9](FULL-PORT-STEP9.md)에 기록했다. 아래 내용은 이 단계 당시의 범위다.

2026-09-16. 원격 main은 `2aaf0532e48016b32571c7929984a8f474e812ee`로 재확인했다. 이전 단계의 통신 계층에 실제 녹음·폴더 병합 실행기를 연결했다. **회의록/분석/수정 이력/프로필/AI 설정의 라이브러리 병합과 자동/수동 WPF 동기화 화면은 아직 구현 중이다.** 전체 이식과 최종 배포/PR을 완료 처리하지 않는다.

## 구현

- `LibrarySyncEngine`: 실제 Worker HTTP 목록을 읽어 녹음·폴더를 비교하고 M4A, 제목, 즐겨찾기, 폴더 배정, 삭제 표시를 양방향 반영한다. 페이지의 개수·ID 중복·순서·진행 여부를 검사한다. 한 녹음의 파일 오류가 다른 녹음 처리를 막지 않는다. 녹음 중인 항목은 복구하거나 전송하지 않는다.
- `SyncRecordings`: Windows 메타데이터에 서버의 수정 시각과 mutation ID를 유지한다. 기존 설치의 최초 동기화는 파일의 실제 수정 시각을 사용한다. 로컬 편집은 새 시각과 ID를 기록하며, 서버의 재생 속도·무음 건너뛰기·음질 보정·경고도 보존한다. Apple/Worker가 허용하는 빈 제목은 목록에서 기본 이름으로 표시한다.
- `SyncStateStore`: HTTPS 서버별로 별도 acknowledgement와 전송 대기 기록을 저장한다. 실패 횟수·재시도 시각은 재시작 후에도 유지되고, 자동 재시도는 지수 간격을 따르며 수동 실행은 즉시 재시도할 수 있다. 토큰 자체를 파일명이나 상태에 저장하지 않는다. 실제 스케줄러/UI 연결은 다음 단계다.
- `SyncFileTransaction`: 적용할 파일과 해시, 이전 파일을 먼저 저장하고, 영속 manifest 작성 뒤 오디오·파생 자료·메타데이터 순으로 적용한다. `LibraryStore.Load` 전에 미완료 적용을 재개한다. 원본은 `.sync/transactions/<ID>/old-*`와 manifest에 남으며 완료된 교체 사본은 지운다. 동기화 중 바뀐 파일은 덮어쓰지 않는다.
- `JsonDisk.Gate`: 메타데이터·회의록·분석·프로필의 짧은 저장 구간과 동기화 적용이 같은 잠금을 사용한다. 네트워크와 모델 실행은 잠금 밖에서 수행한다. 폴더 저장소의 여러 인스턴스도 디스크의 최신 상태를 다시 읽고 변경한다.
- M4A를 받은 기기는 원본 M4A와 WAV의 버전/해시를 함께 보관한다. 다시 업로드할 때 받은 M4A를 재사용한다. 새 오디오 버전을 받으면 이전 버전의 전사·회의록·분석·수정 이력·로컬 음성 캐시를 이력에 보관하고 현재 경로에서 제거한다.

삭제 상태의 특별한 경우도 검증했다. 오디오 없이 새 버전의 삭제 표시만 도착하면 이전 버전의 음성을 새 버전으로 취급해서는 안 된다. 이 경우 이전 음성을 이력에 보관하고, 복원할 때 새 버전의 M4A가 먼저 존재하도록 업로드/다운로드한다. 같은 버전의 단순 삭제는 기존 오디오를 유지한다.

## 검증

`.\.tools\dotnet\dotnet.exe test Windows/NoteTaker.Tests/NoteTaker.Tests.csproj --no-restore --nologo`: **184 통과, 장치 테스트 5개 건너뜀**.

`LibrarySyncTests`는 별도의 두 라이브러리와 실제 loopback HTTP 서버를 사용한다. 서버는 원본 Worker 핸들러와 실제 SQLite SQL을 실행하고, R2는 파일 저장소 대역이다.

1. 녹음·폴더 양방향 반영, 원본 M4A 바이트 유지, 추가 변경 없는 재실행의 업로드/다운로드 0개
2. 서버의 재생 옵션/경고 유지, 다른 인스턴스의 폴더 이름 변경·삭제 반영
3. 오디오 업로드 후 메타데이터 전송 실패 → Worker와 클라이언트 재시작 → 대기 기록 재사용과 재시도 완료
4. 다운로드 도중 로컬 제목 변경 → 로컬 편집 보존 → 다음 실행에서 서버에 반영
5. 오디오 없는 한 항목의 실패에도 나머지 진행, 진행 중인 녹음의 `IsRecording` 유지
6. 오디오 교체 직후 강제 중단 → 라이브러리 재시작에서 나머지 적용 완료, 이전 오디오 해시 보존
7. 새 오디오 버전과 삭제/복원 조합, 이전 파생 자료 보관, 로컬 키·목소리 파일 보존
8. 전송 취소 후 대기 기록 유지, 잘못된 목록/경로 거절, 기존 설치 수정 시각 보존

기존 WPF 화면은 `--smoke-ui Windows/artifacts/sync-step8-regression`으로 검증했다. 빈 목록, 실제 합성 파형, 즐겨찾기·삭제·복원·검색, 폴더 이동/정렬/삭제, 전사 탭, 라이트/다크 설정, 창 닫기가 통과했다. `folders.png`를 직접 확인했다. 합성 오디오만 사용했으며 이 화면 검증에서 마이크·네트워크를 사용하지 않았다. 이는 새 동기화 UI 검증을 뜻하지 않는다.

## 남은 전체 범위

- 회의록은 생성 당시 원문/화자 전사를 보존해야 한다. 현재 별도의 전사 캐시가 바뀐 뒤 이전 회의록에 새 원문을 붙여 업로드하지 않도록 원문 출처를 저장하고 옛 자료를 검증해야 한다.
- notes/intelligence의 원본 응답 바이트와 revision 보존, 각각의 충돌 규칙, 수정 이력의 순번/cursor와 재전송, 프로필 및 AI 설정 병합을 실행기에 연결한다.
- 자동/수동 동기화, 연결 테스트, 취소, 진행/오류 표시, 녹음·AI·재생·설정 변경·종료와 작업 수명을 조정하는 WPF 연결이 필요하다.
- 복구 기록과 파일이 외부에서 변경됐거나 디스크 오류가 계속되면 자동 덮어쓰기를 중지한다. 현재 복구 이력은 원본 파일을 보존하며, 이력을 정리하거나 충돌을 선택하는 화면은 아직 없다. 여러 파일을 보관할 임시/이력 저장 공간이 필요하다.
- 지속 웹 공유의 실제 WPF/Worker 검증, 긴 오디오의 처리 한도 정합성, 실제 한국어 다자 회의 품질·장치 검증, 최종 self-contained ZIP과 PR까지 계속 진행한다.

실제 Cloudflare D1/R2 배포나 실제 Apple 기기와의 왕복은 이 테스트로 입증하지 않았다. 이 단계는 녹음/폴더 실행기 검증이며 전체 동기화와 전체 Windows 이식의 완료 증거를 대체하지 않는다.
