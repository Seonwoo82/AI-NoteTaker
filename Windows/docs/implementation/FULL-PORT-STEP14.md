## 동작

- 최근 삭제된 항목에서 **영구 삭제…**를 누르면 같은 WPF 외관의 확인 창이 열린다. 기본 버튼은 취소다. 확인한 녹음의 삭제 상태·오디오 버전·수정 ID를 다시 검사하고, 재생/파형 읽기를 닫은 뒤 삭제한다.
- 녹음 폴더의 오디오·전사·회의록·분석·수정 이력, 해당 녹음으로 식별되는 동기화 송신 복사본과 완료된 트랜잭션의 이전 파일을 지운다. 공유 수정 이력 수신함과 그 이력에서는 해당 녹음의 항목만 제거한다. 다른 회의의 데이터는 유지한다.
- 삭제 메타데이터는 바이트 그대로 유지하며 수정 시각/ID를 새로 만들지 않는다. `.purged`는 이 기기의 표시용 표식이다. UI는 숨기지만 동기화는 tombstone을 계속 전달한다. 삭제 도중 실패하면 `.purge-pending`을 남겨 다음 목록 로드에서 재시도한다.
- 삭제 후 30일이 지난 항목은 시작/목록 갱신 때 같은 정리를 수행한다. 파일이 잠겨 있으면 경고를 표시하고 다음 로드에서 다시 시도한다. 연결된 외부 폴더는 삭제 전 검사에서 거부한다.
- 다른 기기에서 복원하면 오디오와 문서를 다시 받으며, 로컬 삭제 표식 제거와 수정 이력 cursor 재설정을 같은 트랜잭션으로 적용한다. 수정 이력을 다시 받아 사용자가 바꾼 참여자 이름·프로젝트도 복원한다. 영구 삭제 상태에서 새 이력이 도착해도 로컬 파일을 다시 만들지 않는다.
- **오디오 내보내기…**는 저장된 WAV를 바이트 그대로 복사한다. 임시 파일에 복사 후 교체하며 취소/실패 시 기존 목적지를 보존한다. 라이브러리 내부와 연결된 외부 경로를 목적지로 삼지 않는다. 녹음 화면과 우클릭 메뉴에서 사용할 수 있다.

## 동기화 완료 경합

포터블 WPF 동기화 검사에서 자동 실행의 결과가 사라지는 실패를 관찰했다. 작업 완료 시 `runningWork`를 비운 뒤 외부 `SynchronizeAsync`가 종료 상태를 확정하기 전, UI 이벤트/타이머가 다음 동기화를 시작할 수 있었다. 이전 실행의 마지막 정리가 새 실행의 `syncing` 상태와 겹쳤다.

완료 중 이름 변경 버튼이 다시 활성화되는 이벤트에서 동기화를 재요청해 재현했다. `sync-step14-race-evidence/completion-reentry.json`은 `requests: 1, started: true`이며 WPF 결과가 다시 준비 중으로 바뀌었다. `SyncBusy`가 `syncing`도 확인하도록 수정한 뒤 `sync-step14-race-fixed`에서는 같은 요청이 `started: false`였고 전체 WPF/Worker 동기화 검사가 통과했다. 최초 보조 검사는 녹음 버튼이 동기화 중에도 활성화되는 점 때문에 완료 시점을 관찰하지 못했으므로 이 증거에서 제외했다.

이는 실제 UI 이벤트에 대한 회귀 검사이며 시간을 늘리거나 성공할 때까지 반복해 숨긴 실패가 아니다. 자동/수동 실행, 모달 대기, 오프라인 재시작, 오디오 버전 교체, 설정·녹음·종료의 취소 대기도 함께 통과했다.
