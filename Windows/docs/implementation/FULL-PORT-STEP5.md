# 회의 분석과 프로젝트 브리핑

기준: upstream `2aaf0532e48016b32571c7929984a8f474e812ee`의 F-004–007 및 F-009. 전체 Windows 이식의 한 단계이며 최종 배포/PR 완료 기록이 아니다.

## 구현

- 참여자 발화에서 약속·요청, 질문·답변, 제안/우려/수정/보류/결정을 추출한다. 수동 화자 수정과 텍스트 프로필을 반영하되 원래 전사·회의록·음성 파일은 수정하지 않는다.
- UTF-8 입력 예산에 맞춰 발화를 분할하고 앞 구간의 최대 3개 발화를 참고한다. 각 구간은 새로운 발화를 포함하고 최대 80회 호출한다. 모든 부분 결과를 검증한 후 한 번에 저장한다. 한 발화가 모델 입력을 초과하면 이전 결과를 유지하고 큰 모델 선택을 안내한다.
- 실제 발화 ID, 알려진 화자, 답변 상태, 근거에 있는 기한 표현을 검증한다. 취소·잘못된 JSON·근거 오류·동시 수동 수정·문서/오디오/전사/프로필 변경·녹음 삭제 시 새 분석을 공개하지 않는다.
- Apple과 같은 U+001F 구분자 및 SHA-256 앞 8바이트 ID로 분석 항목을 연결한다. 같은 근거와 속성의 표현만 바뀌면 기존 업무 상태 수정이 이어진다. 근거/담당/기한 등이 바뀌어 ID가 달라지면 이전 수정은 미연결 이력으로 남는다.
- WPF의 `회의 분석` 탭에 약속·요청 / 질문·답변 / 결정 흐름 / 프로젝트 화면, 전체·내 관련·확인할 항목 필터, 업무 미완료·완료·제외, 프로젝트 설정·해제를 추가했다. 근거 보기는 원본 회의의 해당 발화만 표시하고, 듣기는 해당 PCM 구간을 연결하는 기존 플레이어를 사용한다.
- 프로젝트 브리핑은 최근 회의 순으로 결정·열린 업무·미해결/불확실 질문을 각각 최대 12개 집계한다. 프로젝트 하나이면 자동 선택하며, 수동 업무 상태와 프로젝트 수정을 반영한다. 다른 회의 근거를 열 때 검색과 폴더 필터를 해제해 원본 회의에 도달한다.
- 녹음 후 자동 분석 설정은 참여자 준비가 성공한 다음 회의 분석으로 이어진다. 참여자 분석 취소/실패나 앱 종료 시 다음 분석을 시작하지 않는다.

## 로컬 모델 검증 과정

일반 요약과 같은 `think=false`, 출력 4096으로 작성한 한국어 전사를 실제 Qwen 3.5 4B에 보냈을 때 형식 오류와 길이 초과가 발생했다. JSON schema와 8192 출력만 추가한 실행에서도 같은 업무가 반복됐다. 이 실패들은 기존 분석을 덮어쓰지 않았다.

현재 로컬 회의 분석은 구간별 **업무→질문→결정의 세 호출**로 나눈다. 알려진 화자/발화 ID를 enum으로 제한한 JSON schema, 추론 비활성화, 출력 8192/문맥 32768, temperature 0.2, repeat penalty 1.1을 사용한다. 세 호출을 합쳐 최대 80회이며 일부 결과만 공개하지 않는다. 한 번에 세 범주를 요청하거나 추론을 켠 실험은 반복 또는 추론 중 길이 초과로 실패했다. 이 실험 설정은 제품에 적용하지 않았다. 일반 요약의 8192 문맥/4096 출력/추론 비활성화 설정은 유지한다.

모델이 날짜에 공백만 삽입한 경우에는 인용한 발화 안에서 유일한 원문 구간을 찾을 때만 원래 표현으로 복원한다. 숫자·날짜·구두점 변경, 인용하지 않은 발화 사용, 서로 다른 후보가 있는 경우는 복원하지 않으며 검증에서 거절한다. 모든 응답은 스키마 제한 이후에도 근거와 상태를 다시 검증한다.

공식 근거: [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs), [chat API](https://docs.ollama.com/api/chat). 이전 버전의 Qwen/format 문제가 보고됐지만 현재 사용한 런타임은 **0.34.0**이며, 이 실행의 실패 원인을 이전 버전 이슈와 동일하다고 단정하지 않는다.

## 검증 상태

- 자동 테스트: 135 통과, 5개 실제 장치 테스트는 실행하지 않았다.
- 기본 WPF 회귀: `Windows/artifacts/meeting-regression-ui` 실행 성공.
- 실제 로컬 모델 + WPF: `Windows/artifacts/meeting-analysis-final/result.json` 성공, 24.81초. 작성한 한국어 전사에서 업무 5/질문 3/결정 3을 생성했다. 실제 버튼으로 업무 완료와 열린 업무 필터, 프로젝트 자동 선택, 정확한 근거 목록 및 다른 회의 이동, 원본 파일 보존을 확인했다. 라이트/작은 다크 창 렌더를 직접 확인했다.
- 새 self-contained 폴더의 EXE: `Windows/artifacts/meeting-portable-smoke/result.json` 성공, 24.34초. 업무 5/질문 2/결정 3. 같은 흐름에 더해 실제 프로젝트 편집 대화상자의 저장·이름 비우기·재연결까지 확인했다.
- 같은 포터블 EXE의 `Windows/artifacts/meeting-auto-profile-smoke/result.json` 성공. 공개 중국어 파일 입력의 녹음 완료 후 실제 Whisper/Sherpa 참여자 분석, 이어서 Ollama 구조화 분석이 저장될 때까지 기다려 확인했다. 등록/취소/삭제/라이브 본인 표시와 수동 이름 보존도 회귀 검증했다.
- 최종 소스의 `Windows/artifacts/meeting-final-review/result.json` 성공, 23.97초. 프로젝트 대화상자가 열린 동안 선택 회의가 바뀌는 상황을 추가해, 편집 시작 시의 회의에만 저장되는 것을 확인했다. 분석 필터 변경 시 전체 라이브러리를 불필요하게 다시 읽지 않도록 했다.
- 두 실행의 차이는 모델 출력 변동이며, **위 성공은 UI/저장/근거 ID 검증의 성공이다. 의미 정확도의 합격을 뜻하지 않는다.** 수작업으로 내용을 읽었을 때 4B 모델이 출시/예산 보류/기능 제외 결정을 업무로 중복 분류했고, 한 실행에서는 보류 발언을 미응답 질문으로 잘못 분류했다. 이 모델의 의미 분류 정확도는 후속 모델 비교와 실제 회의 검증 대상이다. 사용자는 근거를 확인하고 잘못된 업무를 제외하거나 다른 선택 모델로 재분석할 수 있다.
- `--smoke-meeting`은 작성한 한국어 전사와 무음 WAV를 사용한다. 마이크 녹음·물리 재생·음성 인식 정확도의 증거가 아니다. API 키·유료 호출은 사용하지 않았다.

재현:

```powershell
./.tools/dotnet/dotnet.exe test Windows/NoteTaker.Tests/NoteTaker.Tests.csproj -c Release
./.tools/dotnet/dotnet.exe run --project Windows/NoteTaker.Windows -c Release -- --smoke-meeting Windows/artifacts/meeting-check "$env:LOCALAPPDATA/AI-NoteTaker"
```
