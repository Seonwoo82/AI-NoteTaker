# 재생 명령 보호와 9B 로컬 모델 비교

2026-09-16. 프로필 창과 녹음 전환 중의 대기 중 재생 명령을 검사하고, 동일한 한국어 자연 대화 전사로 더 큰 로컬 모델을 비교한다. 전체 Windows 이식 완료나 실제 업무 회의 정확도를 뜻하지 않는다.

## 재현한 재생 충돌과 수정

프로필 창을 열 때 진행 중인 내 발화 재생은 중단되지만, 이미 전달된 더블클릭 이벤트는 비활성화된 버튼을 거치지 않고 다시 재생할 수 있었다. 실제 WPF 프로필 창을 연 상태에서 발화 목록의 routed 이벤트를 전달해 `Queued turn playback started while profile was open` 실패를 재현했다. 일반 재생 버튼도 같은 방식으로 `Queued regular playback started while profile was open` 실패를 확인했다.

일반 재생·시간 이동·발화 재생 진입점은 `CanControlPlayback`으로 녹음/AI 작업/전환/모달/종료 상태를 함께 확인한다. 발화 재생에는 삭제 상태 검사도 적용한다. 일반 녹음과 최근 삭제 목록의 기존 일반 재생 정책은 바꾸지 않는다.

별도 opt-in 실행인 `--smoke-playback-guards <output>`는 생성한 5초 무음 WAV와 실제 출력 장치를 사용한다. 다음을 확인했다.

- 내 발화 재생이 시작되고, 실제 프로필 창을 열면 중단된다.
- 프로필 창 안에서는 대기 중 일반 재생·시간 이동·발화 더블클릭이 모두 거부된다.
- 녹음 시작 전환 중 발화 재생과 삭제된 녹음의 발화 더블클릭이 거부된다.
- 원본 WAV 해시가 유지된다. 입력 장치는 없는 fixture로 주입하므로 마이크 녹음이나 목소리 등록 시작은 실행하지 않는다.

증거: `Windows/artifacts/playback-guards-before/error.txt`, `playback-guards-regular-before/error.txt`, `playback-guards-all-fixed/result.json`. 변경 후 WPF Release 빌드는 경고/오류 0이며 `ui-step16/result.txt`, `library-commands.json`, `library-files.json`도 통과했다. 후자는 실제 WPF 명령·이름 변경 창·파일 처리 경로이며 OS 파일 선택창과 공유 창 presenter는 fixture다. 사람의 실제 음성 청취나 물리 키 입력 증거는 아니다.

## 로컬 9B 모델 준비

평가 도구에 `prepare-summary <output> <modelRoot> qwen3.5:9b`를 추가했다. 제품의 `LocalRuntime.PrepareOllamaAsync`를 별도 loopback 포트 11436에서 사용하며, 기존 서버가 있으면 중단한다. 사용자 AI 설정과 기본 4B 선택은 바꾸지 않는다.

모델 준비는 270.38초에 완료됐다. 설치된 manifest SHA-256은 `6488c96fa5faab64bb65cbd30d4289e20e6130ef535a93ef9a49f42eda893ea7`이고 실제 `/api/show`는 9.7B/Q4_K_M을 반환했다. 증거: `Windows/artifacts/qwen9b-prepare/result.json`. 모델/런타임 다운로드 외 클라우드 추론과 사용자 녹음은 사용하지 않았다.

모델 설명: [Ollama Qwen3.5 9B](https://ollama.com/library/qwen3.5:9b), [Qwen 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-9B). 다른 크기의 공개 벤치마크 수치를 이 9B 구성의 결과로 사용하지 않는다.

## 같은 자연 대화의 비교

단계 12의 1,244.80초 공개 한국어 자연 대화에서 측정한 Whisper 전사와 Sherpa 화자 결과를 새로운 격리 라이브러리로 복사해 `conversation` 평가 명령으로 실행한다. 정답은 모델 입력에 포함하지 않는다. 모델이 기존 전사 오류와 불명확한 화자 배정을 전달받는 조건이며, 업무 회의 정답 기반 정확도 평가가 아니다.

두 모델 모두 파이프라인이 완료됐고 음성과 원문 전사 해시가 유지됐다. 결과는 각각 `Windows/artifacts/korean-dialogue/meeting-qwen4b/`, `meeting-qwen9b/`의 `result.json`, `notes.json`, `analysis.json`이다.

| 측정 | Qwen3.5 4B | Qwen3.5 9B |
| --- | --- | --- |
| 회의록 단계, 전사 정리 시도 포함 | 108.40초 | 106.22초 |
| 구조화 분석, 21회 호출 | 94.94초 | 122.96초 |
| 업무 / 질문 / 결정 개수 | 1 / 9 / 0 | 0 / 19 / 0 |
| 전사 정리 | 출력 미완료, 원문으로 진행 | 내용 보존 검사 실패, 원문으로 진행 |

같은 개발 PC의 각 한 번 실행이다. 9B 실행 중에는 CPU를 사용하는 WPF 빌드/무음 재생 검사도 수행했으므로 통제된 성능 벤치마크나 속도 우열을 주장하지 않는다. 입력 발화 400개, 표시 화자 4개, 미확인 발화 214개는 두 실행에서 같다. 두 모델 모두 로컬 실행이며 유료 API를 호출하지 않았다.

결과를 원문과 대조하면 9B에도 오류가 남는다. 자기소개를 질문으로 분류한 4B의 해당 항목은 없어졌지만, 과거 극장 방문 습관을 설명하는 문장을 질문으로 바꿔 분류했다. 영화판의 시간 제약 때문에 묘사가 생략된다는 발화가 있는데 요약은 TV 오리지널 쪽에 그 제약을 붙였다. 요약 끝의 미해결 질문 없음과 별도 분석의 미답변 질문 목록도 일치하지 않는다. 질문 개수가 늘었다는 이유로 더 정확하다고 평가하지 않으며 기본 4B 선택을 자동 변경하지 않는다.

9B를 선택해 준비·추론·저장할 수 있다는 실행 증거다. 실제 업무 회의의 의미 정확도나 한국어 품질 개선을 입증한 결과는 아니며, 전사 정리 검증을 완화해 통과시키지 않았다. 공개 음성과 생성 내용은 ignored artifacts에만 두고 저장소/ZIP에 포함하지 않는다.

## 배포 범위

현재 단계 15 ZIP에는 이 단계의 재생 보호 수정이 포함되지 않는다. 기존 ZIP의 9개 성공 경로와 네이티브 공유 미완료 상태를 유지하며, 최종 배포에는 수정된 소스의 별도 ZIP 검사 결과가 필요하다. 네이티브 공유 이벤트/실제 창, 물리 폴더 드래그, 실제 사용자 마이크·장시간 회의·Apple 기기·배포 Cloudflare 서버 검증은 이 문서의 통과 범위에 포함하지 않는다.
