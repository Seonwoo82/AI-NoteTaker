## 지속 웹 공유

공유 창에 새로고침을 추가했다. 서버에서 생성·해제한 뒤 응답을 받지 못하면 성공이나 실패를 추측하지 않고 변경 버튼을 잠근다. 새로고침으로 서버의 현재 주소와 상태를 복구한 다음 다시 조작할 수 있다. 창과 앱 종료는 진행 중인 요청을 취소하고 완료를 기다린다. 공유·이름 변경 등을 포함한 모든 열린 모달에서는 자동 동기화와 녹음 시작을 미룬다.

실제 WPF와 Worker HTTP/SQLite 검증 결과는 `Windows/artifacts/sharing-step11-ui/result.json`이다. 생성 후 창 재열기, 앱과 서버 재시작 후 같은 주소 복원, 반복 복사, 익명 HTML 열람, 원문 변경 후 스냅샷 유지, 해제 후 새 스냅샷 생성, 이전 주소 404, 만료 후 404, 서버 저장 후 응답 유실·새로고침 복구, 오프라인 복구, 종료 시 취소 대기를 확인했다. 실제 요청에서 제목과 Markdown만 전송되는 것도 검사했다.

R2는 파일 시스템 대체 구현이고, 만료 시각은 fixture SQLite에서 앞당겼다. 복사 버튼은 테스트용 수신 함수를 사용했으며 사용자의 클립보드를 변경하지 않았다. 실제 Cloudflare 배포나 Apple 실기기 검증을 뜻하지 않는다. 밝은 화면과 복구 후 어두운 화면을 PNG로 렌더하고 확인했다.

## 긴 녹음의 화자 처리

기존 화자 worker의 전체 오디오 4시간 로딩 경로를 개선했다. 5분을 넘는 파일은 5분 단위로 읽고 앞뒤 2초를 겹쳐 분석한다. 결과는 겹친 문맥을 제거해 원본 절대 시간에 연결한다. 상세 전사와 화자 분석의 지원 길이를 모두 6시간으로 맞췄다.

구간마다 달라지는 화자 번호를 그대로 이어 붙이지 않는다. 음성 특징이 양방향으로 충분히 일치할 때 같은 참여자에 연결한다. 인원을 지정하면 전체 구간의 후보를 통합하며 동시에 말한 서로 다른 사람은 합치지 않는다. 불확실한 구간은 미확인으로 남기고 완료 전 실패·취소 시 기존 문서를 보존한다. 메모리 할당은 구간 크기로 제한하며 정확히 0인 디지털 무음만 모델 호출을 생략한다.

실제 Sherpa worker로 6시간 PCM 파일을 처리했다. 공개 중국어 4인 음성을 0초, 290초, 14,400초, 21,520초에 배치하고 나머지는 디지털 무음으로 채운 fixture다. 자동 인원 추정과 4명 지정 양쪽에서 네 대표 화자의 ID가 네 위치에서 유지됐고, 5분 경계·4시간 이후 처리·원본 해시 보존·소유 worker 취소를 확인했다.

- 자동 인원: `Windows/artifacts/long-speakers-auto-step11/result.json`, 4명, 최대 작업 집합 약 814MiB.
- 4명 지정: `Windows/artifacts/long-speakers-step11/result.json`, 4명, 최대 작업 집합 약 815MiB.
- 처리와 후속 검사를 합친 측정은 각각 약 33초/32초다. 대부분이 정확한 디지털 무음인 fixture이므로 **실제 6시간 회의의 처리 속도나 인식 정확도를 나타내지 않는다**.
