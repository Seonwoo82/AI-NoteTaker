# 이름·용어·목소리 프로필과 라이브 본인 표시

2026-09-16, `codex/windows-complete-port`. 전체 이식 중 세 번째 단계의 구현·검증 기록이다. 최신 Apple 앱의 전체 기능, 한국어 실제 회의 정확도, 최종 공개 배포 완료를 뜻하지 않는다.

## 사용 흐름

상단 **프로필**에서 이름·별칭·역할·용어를 저장한다. 회의록 요약은 이 정보를 참고 데이터로 전달하며, 녹음 원본과 전사문은 변경하지 않는다. 참여자 목록에는 들리는 표현과 등록된 표기의 대응을 주석으로 표시한다. **녹음이 끝나면 참여자 자동 분석**은 기본 해제이며, 켜면 녹음 저장 후 Whisper 등 선택한 전사 엔진과 로컬 화자 분석을 실행한다. 일반 회의록 자동 생성과 독립 설정이다.

**내 목소리**에서 명시적으로 녹음을 시작하고 10–30초의 혼자 말한 음성을 등록한다. 완료된 오디오의 실제 길이를 검사하고 30초를 넘으면 앞 30초만 사용한다. 말소리 부족·여러 목소리·취소·실패 때 이전 프로필을 유지한다. 등록용 오디오는 성공·취소·실패·창 닫기 후 제거한다. 삭제는 음성 프로필에만 적용되며 이름/용어를 지우지 않는다.

일반 녹음 중 최근 3초의 PCM을 메모리에서 읽어 소유한 로컬 worker의 표준 입력으로 보낸다. 라이브 분석용 오디오 파일을 만들지 않는다. 한 번에 하나의 추론을 실행하며 나·다른 참여자·불확실·무음 상태를 표시한다. 일시정지 때 최근 오디오를 비우고 진행 중 추론을 취소하며, 이전 추론 결과가 재개 후 표시되지 않도록 세대를 확인한다. 녹음 완료·종료는 worker 종료도 기다린다.

목소리 등록/변경/삭제 후 기존 회의의 로컬 음성 특징과 오디오 해시를 확인해 본인 표시를 다시 적용한다. 수동 이름과 본인 지정은 별도 수정 이력으로 유지되어 자동 결과보다 우선한다.

## 데이터와 실행

- `meeting-profile.json`: Apple 이름/용어 JSON 계약, 최대 60KiB. 프롬프트 참고 정보는 최대 UTF-8 12,000바이트. JSON에 목소리와 계산용 프롬프트 속성을 넣지 않는다.
- `voice-profile-local.json`: 이 PC의 3D-Speaker 512차원 벡터와 모델 ID. 다른 모델/차원은 재등록해야 한다. 아직 전체 동기화는 구현 중이며 이 파일과 `speaker-acoustic-local.json`은 업로드 대상에서 제외해야 한다.
- 프로필 저장은 원본 해시로 동시 변경을 거부하고 원자적 파일 저장을 사용한다. 잘못된 새 데이터나 손상된 기존 텍스트 프로필을 자동 덮어쓰지 않는다.
- 런타임과 모델은 Step 2의 고정 버전/해시/라이선스를 사용한다. 프레임은 표준 입력, 결과는 소유한 임시 JSON으로 전달하고 회수한다. 개발 실행에서 로컬 SDK를 찾아 worker에 전달하는 경로도 수정·실행 검증했다.

## 확인한 증거

`dotnet test Windows/NoteTaker.Tests/NoteTaker.Tests.csproj -c Release`: **107 통과, 5 하드웨어 테스트 건너뜀**. 신규 테스트는 프로필/음성 분리, 낡은 수정과 잘못된 교체 거부, 손상 파일 보존, UTF-8 한도, 결합 문자·이모지의 정확한 UTF-16 주석 범위, 요약 참고 데이터와 전사 원문 보존, 원형 오디오 버퍼, 라이브 취소/단일 작업/무음/실패를 확인한다.

`--smoke-profile <output> <public-four-speaker-wav> <model-root>`는 파일 기반 녹음 구현을 주입해 **사용자 마이크를 열지 않고** 실제 WPF 이벤트와 Sherpa worker를 실행한다. 프로필 저장, 등록·재등록 취소·삭제·등록 중 닫기, 무음 실패 후 이전 프로필 보존과 임시 파일 제거를 검사한다. 일반 녹음 화면에서 실제 모델의 나/다른 참여자 표시와 일시정지/재개를 확인하고, 완료 후 실제 Whisper 중국어 전사 및 Sherpa 자동 참여자 분석을 수행한다. 이후 음성 프로필 재적용이 수동 수정 이력을 보존하는지도 확인한다.

독립적으로 지정한 공개 중국어 발화에서 등록 구간과 분리한 3초 입력을 비교했다. 같은 화자 cosine **0.67235**, 다른 화자 **0.14427**였다. 현재 나 임계값 0.6, 다른 참여자 임계값 0.25 사이에서는 불확실로 처리한다. 새 self-contained EXE에서 해당 단일 입력의 worker 실행은 약 **0.77초**였다. 이는 이 개발 PC와 해당 공개 파일의 실행 결과이며 보편적인 정확도/지연 측정이 아니다.

- `Windows/artifacts/profile-live-smoke/result.json`: 개발 DLL 실행의 전체 흐름 통과.
- `Windows/artifacts/profile-portable-smoke/result.json`: 새 폴더형 self-contained EXE에서 같은 흐름 통과. 외부 SDK 없이 포함한 런타임으로 실행.
- `Windows/artifacts/profile-regression-ui/result.txt`: 기존 라이브러리/파형/폴더/회의록/설정/종료 WPF 회귀 통과.
- 위 프로필 폴더의 PNG: 밝은 화면, 600×650 어두운 화면, 라이브 나/다른 참여자, 자동 본인 참여자 분석을 렌더링하고 확인했다. 작은 창에서 안내문이 잘리던 문제는 스크롤로 수정 후 다시 확인했다.

## 남은 범위

실제 마이크와 시스템 소리가 섞이는 회의, 겹침/잡음/한국어 여러 참여자, 30초 경계의 실제 장치 녹음, 장시간 부하와 실제 이어듣기는 별도 검증이 필요하다. 공개 파일의 양성/음성 비교를 음성 인증 기능으로 사용하지 않는다. 단어별 시간·화자 그룹 변경 후 수정 재연결, 구조화 회의 분석 UI, 프로젝트 브리핑, 정리/보완, 전체 동기화와 최종 배포/PR은 계속 진행 중이다.
