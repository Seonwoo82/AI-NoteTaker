# 모델 선택, 회의록 보완과 전사 정리

확인: 2026-09-16. 기준 upstream `2aaf0532e48016b32571c7929984a8f474e812ee`. 전체 이식 중 여섯 번째 단계이며 전체 동기화·최종 배포 완료 기록은 아니다.

## 구현

- 공개 모델 목록의 기본/전사 엔드포인트를 병합해 검색한다. 목록 요청에는 API 키를 보내지 않는다. 실패/검색 결과 없음/목록에 없는 수동 ID 때문에 기존 선택을 지우지 않는다. 문맥·최대 출력·조회 시점 가격을 표시하고 검증된 목록을 기기에 저장한다.
- 보완용 모델을 따로 선택하거나 회의록 모델을 따른다. 로컬 4B/9B도 각각 선택한다. 키만 삭제해도 선택한 모델과 엔진을 유지한다.
- Apple `MeetingCompletionBudget`의 문맥·제공자 출력·GLM-5.3 reasoning 예산·부분 출력 상한·대기 시간을 적용한다. 모르는 모델은 작은 기본 문맥으로 처리한다. 로컬 일반 생성은 16K 문맥/4K 출력, 구조화 생성은 32K/8K이다.
- 보완 요청 → 수정안/현재 회의록 비교 → 적용 또는 버리기. 미리보기는 파일을 쓰지 않는다. 요청을 바꾸면 이전 수정안 적용을 막는다. 종료 시 작업을 취소하고 기다리며 보완 창이 열려 있는 동안 녹음 시작과 프로필 작업을 막는다.
- 적용 전에 오디오 해시와 metadata/notes/transcript/intelligence/수정 이력/프로필 저장 상태를 다시 확인한다. 중간 변경·삭제·취소·실패 시 현재 자료를 보존한다. 보완 이력은 원래 생성 모델과 별도로 저장한다.
- 전사 정리는 문단 또는 발화 ID·원문 해시에 연결해 원문과 별도 저장한다. 유지한 텍스트의 숫자·시간, ID 누락/중복, 과도한 삭제를 검증한다. 문자·숫자가 없는 잡음은 빈 결과를 허용하며 의미 정확도는 여전히 원문과 비교해야 한다.
- 자동 정리는 기본 활성화이며 끌 수 있다. 실패하면 원문으로 회의록을 만들고 이유를 표시한다. 수동 재정리 실패는 기존 자료를 보존한다. 원본 비교 탭, 정리본 내보내기, 정리한 참여자 발화 표시를 제공한다.
- 목차는 H1–H6의 실제 WPF 문단으로 이동한다. 같은 제목도 개별 위치를 가지며 fenced code 안의 제목을 제외한다. `C#` 같은 실제 문자는 보존한다.

## 검증

새 단위 테스트는 공개 목록 병합/실패 보존, 출력 예산과 HTTP 본문, 독립 모델 선택, Unicode 문서 전체 분할, 정리 ID/숫자/시간, 자동 실패 후 원문 사용, 정리본 재사용, 미리보기/취소/동시 변경을 검증한다. HTTP 본문 테스트는 주입한 핸들러를 사용하며 유료 추론 검증은 아니다.

긴 보완 문서의 경계 테스트에서 이모지·줄바꿈의 JSON 이스케이프 크기를 놓친 오류를 발견했다. 직렬화된 문자열 크기로 분할하도록 고쳤으며 조각을 모두 이어 붙인 결과가 원본 전체와 같은지도 확인한다.

실제 Qwen3.5:4B의 첫 전사 정리 호출은 닫히지 않은 JSON을 반환했다. 로컬 구조화 출력에 ID와 배열 크기를 제한하는 schema를 전달하도록 수정했다. 그 후 실제 로컬 정리와 보완을 WPF에서 적용했다.

정리본을 직접 읽었을 때 일부 한국어 단어 내부에 공백을 넣거나 조사를 바꾸는 품질 저하도 확인했다. 문자·숫자 순서 변경은 동일 구문의 명백한 3회 이상 반복 축소를 제외하고 해당 원문을 유지한다. 원래 붙어 있던 한글 단어에 새 공백을 넣는 불확실한 수정도 원문을 유지한다. 이 보수적 규칙은 일부 올바른 띄어쓰기 수정도 포기하며, 원문 오탈자를 AI가 임의로 교정하지 않는다. 숫자 변경과 과도한 삭제는 계속 실패로 처리한다.
