# 공유 주소 재진입·재시작 복원

## 문제와 변경

이전 구현은 링크 주소를 공유 창의 일시적인 상태에만 보관하고, 서버 상태 조회는 활성 여부와 만료 시각만 반환했습니다. 그 결과 창을 닫으면 활성 링크가 있어도 주소와 복사 버튼이 사라졌습니다.

이제 인증된 상태 조회가 기존 URL도 반환합니다. Mac·iPhone·Windows는 새 공유 창과 새 프로세스에서 같은 주소를 불러오며, 주소 클릭과 오른쪽 복사 버튼으로 전체 링크를 복사합니다. 주소 표시를 위해 공유를 취소하거나 새로 만들 필요가 없습니다. 다른 서버·계정의 오래된 응답이나 취소된 공유 주소는 표시하지 않습니다.

## 저장과 기존 링크 보존

마이그레이션 `0007_persistent_share_urls.sql`은 비공개 D1에 조회 가능한 토큰 필드와 고유 인덱스를 추가합니다. 관리 API는 기존 동기화 키로 인증하며, 토큰은 공개 목록이나 로그에 노출하지 않습니다. 새 공유는 해시와 조회 가능한 토큰을 함께 저장합니다.

기존 해시 전용 레코드는 원래 링크를 계속 허용합니다. 원문을 알고 있으면 해시를 확인한 뒤 같은 주소를 복원하고, 그렇지 않은 경우에는 기존 링크와 만료 시각을 유지하는 안정적인 별칭을 조건부로 저장합니다. 동시 조회·재게시·공유 취소 중에도 유실된 상태를 되살리지 않도록 현재 레코드를 다시 확인합니다. 공유 취소와 만료는 원래 주소와 별칭에 모두 적용됩니다.

운영 환경에서는 사용자가 이미 전달한 원래 주소를 해시로 검증해 그대로 복원했습니다. 기존 링크·스냅샷·만료 시각을 유지했습니다. 적용된 Worker 버전은 `33decc2f-71ca-482a-9236-035319c36e62`입니다.

## 검증

- 서버 테스트 91개 통과. 실제 SQLite와 새 Worker 프로세스에서 URL 복원, 기존 링크, 동시성, 공유 취소, 만료, 마이그레이션 상태 점검 포함.
- Mac·iPhone 각각 클라이언트/상태 테스트 14개와 클립보드/화면 테스트 2개 통과.
- Windows Release win-x64 빌드와 실제 클라이언트 소스를 실행한 별도 .NET 검증 통과. Windows 네이티브 UI 실행은 이 Mac에서 검증하지 않았습니다.
- 운영 서버에서 원래 URL이 반복 조회되고 기존 공개 링크가 계속 열리는 것을 확인했습니다. 테스트용 공유의 취소와 URL 제거도 확인했습니다.
- 설치된 Mac에서 공유 창 닫기/재열기와 프로세스 완전 종료/재시작 후 주소·복사 버튼을 확인했습니다. 버튼과 주소 클릭으로 복사된 클립보드 값이 원래 URL과 동일했습니다.

Mac 1.7.3(빌드 22), iPhone 1.7.2(빌드 25), Windows 소스 0.3.2에 반영했습니다.

실물 iPhone은 업데이트 설치와 버전 조회를 확인했지만, 기기가 잠겨 있어 실행 검증은 완료하지 못했습니다. iPhone의 클라이언트·상태·화면 검증은 시뮬레이터에서 수행했습니다.
