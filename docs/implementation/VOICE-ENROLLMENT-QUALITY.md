# 작은 음량의 목소리 등록 — 1.4.1

## 확인한 원인

첨부 화면의 14초는 타이머가 아닌 실제 수신한 PCM 샘플 길이였다. 최소 10초를 넘었지만, 저장 전 검사에서 전체 녹음의 RMS가 0.01 미만이면 실패했다. 이 값은 말소리 여부와 관계없이 작은 입력이나 앞뒤 무음을 포함한 녹음을 거절했다.

공개 LibriSpeech 14.225초 음성은 원래 RMS 약 0.0385이며, 음량을 20dB 낮추면 약 0.00385다. 충분한 말소리가 있어도 기존 검사에 걸린다. 낮은 음량과 무음을 섞은 14초 회귀 테스트에서 첨부 화면과 같은 오류를 먼저 재현했다.

## 수정

- 최소 녹음 시간 10초와 최대 30초는 유지한다. 녹음 길이 부족, 마이크 입력 부족, 말소리 판별 실패를 서로 다른 메시지로 표시한다.
- 20ms 단위 입력 에너지로 음량과 입력 감지 시간을 측정한다. 이 수치는 ‘음성 인증’이나 말소리 판정이 아니다. 화면의 입력 막대로 무음이나 잘못된 마이크 입력을 저장 전에 확인할 수 있다.
- 전체 평균 음량 기준을 제거하고 입력이 있는 구간을 확인한다. 실제 모델 처리에서는 DC 성분과 조용한 앞뒤 구간을 제거하고, 최대 32배의 제한된 이득과 피크 제한으로 작은 신호를 보정한다.
- 이미 설치된 pyannote 모델로 실제 말소리를 검사한다. 새로운 모델 다운로드나 외부 서비스는 필요하지 않다. 겹치지 않은 단일 화자 구간이 3초 이상인 후보만 사용한다.
- WeSpeaker의 10초 입력 창에 맞춰 5초 간격으로 후보를 평가하고 말소리가 가장 충분한 창을 선택한다. 녹음 앞부분이 조용하다는 이유로 뒤의 목소리를 놓치지 않게 한다.
- 실패·취소 시 기존 목소리 프로필을 유지하며, 원본 등록 오디오를 저장하거나 동기화하지 않는다. 기존 화자 비교 임계값과 일반 회의 화자 분석은 바꾸지 않는다.

## 검증

- `enrollment-quality-red.log`: 14초의 작은 음성·무음 입력에서 기존 오류 재현.
- `enrollment-quality-green.log`: 같은 입력의 등록 성공, 무음/상수 DC/잘못된 PCM 거부, 제한된 음량 보정 검증.
- 실제 pyannote·WeSpeaker: 공개 음성을 20dB 줄이고 앞뒤 무음을 추가한 녹음을 **OwnerVoiceManager의 실제 등록 경로**로 처리했다. RMS 약 0.00331인 샘플의 등록이 성공했다.
- 서로 다른 공개 발화를 이용한 동일 화자 비교 cosine 약 0.844, 다른 화자 약 0.208. 같은 화자 판정은 유지되고, 잡음 전용 샘플은 등록을 거부했다. 수치는 제한된 공개 샘플의 회귀 검증이며 일반적인 정확도 보장은 아니다.
- 모델 검증은 기존 로컬 캐시를 사용하고, 사용자 마이크·개인 목소리는 수집하지 않는다. 결과는 `build/fluidaudio-validation/quiet-enrollment-*.json`에 기록한다.

iPhone의 1.4.1 (13) 설치값을 다시 확인했다. 기기가 잠겨 앱 실행 요청은 거부되었으므로, 실제 기기의 녹음·저장 확인은 잠금 해제 후 필요하다.
