# 참여자 전사와 AI 회의록 보완 — 1.4.0

## 사용 흐름

**AI 회의록 → 전사문**에서 발화를 `참여자 1: 내용`, `참여자 2: 내용`으로 표시한다. 번호는 같은 전사문에서 각 화자가 처음 등장한 순서로 정하며, 다시 등장한 화자는 같은 번호를 유지한다. 미확인 화자나 사용되지 않은 내 목소리 프로필에는 번호를 부여하지 않는다.

새 회의록을 만들 때 기존 화자 전사 결과를 우선 사용하고, 필요하면 타임스탬프 전사와 FluidAudio를 실행한다. 예전의 일반 전사문은 **참여자 구분**으로 변환할 수 있다. 전체 회의 분석의 약속·질문·결정 생성 요청은 추가하지 않는다. 타임스탬프를 반환하지 않는 전사 모델이나 음성 분석 실패 때는 기존 일반 전사문을 유지한다. 겹치거나 불분명한 목소리는 잘못된 화자 번호를 만들어 붙이지 않는다.

**AI 설정 → 회의록 보완 모델**에서 별도 모델을 고른다. 기본값 **회의록 모델과 동일**은 현재 회의록 모델을 따른다. 이 선택은 Cloudflare로 동기화하고 API 키는 각 기기에 보관한다.

회의록의 **AI 보완**에서 다음과 같은 요청을 입력한다.

> 승원과 승현은 같은 사람이며 정확한 이름은 승원입니다. 제안서는 내일이 아니라 다음 주에 전달하기로 합의했습니다.

**보완안 생성 → 미리보기 → 보완안 적용** 순서로 반영한다. 미리보기를 버리거나 작업을 취소하면 기존 회의록은 변하지 않는다. 원래 전사문은 보완 AI가 수정하지 않는다. 적용한 보완 모델과 최근 수정 지시는 문서에 기록된다.

## 구현과 보존 규칙

- 번호 표시는 `NumberedTranscript`, 보완 요청 분할은 `MeetingEnhancementPrompts`를 Mac/iOS가 공유한다.
- `MeetingNotesService`의 기존 큐·취소·전사 캐시·문서 저장 경로를 재사용한다. 보완할 때 오디오를 다시 전사하지 않는다.
- 긴 회의록은 기존 문단을 누락하지 않고 최대 32개 요청으로 나눈다. 각 요청에 사용자 수정 의도와 관련 전사문 발췌를 제공하고, 새 맥락 추가는 마지막 부분에서만 수행하게 지시한다.
- 보완 생성과 적용 시 메모리 및 디스크의 원본 문서를 비교한다. 다른 기기 동기화·재생성·삭제·오디오 교체가 발생했으면 오래된 보완안의 적용을 거부한다.
- 출력과 모델 한도는 기존의 최대 131,072토큰 예산을 사용한다. 길이 제한/빈 응답/네트워크/저장 오류 시 이전 문서를 덮어쓰지 않는다.
- `speakerTranscript`, `enhancement`는 기존 notes JSON의 선택 필드다. 서버는 화자 전사 ID와 오디오 버전, 필드 허용 목록, 크기를 검사한다. 음성 임베딩이나 API 키를 이 문서에 넣지 않는다.
- 이전 클라이언트가 보완 모델 필드를 생략하면 현재 선택을 유지한다. 새 클라이언트가 빈 문자열을 명시하면 ‘회의록 모델과 동일’로 되돌린다.

## 검증 범위

참여자 최초 등장·반복·미확인 처리, 화자 캐시 재사용, 전사 모델 변경 시 출처 일치, 기존 분석 결과와 사용자 수정 보존을 검사한다. 보완 테스트는 별도 모델 선택, 수정 지시 전달, 전사 재실행 없음, 미리보기·적용·취소·실패·동기화 충돌을 포함한다. 서버 테스트는 이전 형식과 새 문서의 왕복 및 잘못된 필드 거부를 포함한다.

정적 화면 렌더는 한국어 Mac과 390pt iPhone에서 전사, 수정 입력, 미리보기, 모델 설정을 확인한다. 실제 유료 OpenRouter 보완 요청이나 사용자 목소리 녹음은 자동 테스트에 포함하지 않는다.

## 검증 결과

- Mac 397개, iOS 시뮬레이터 273개 테스트 통과 (`enhancement-*-final-tests.log`).
- Cloudflare Worker 49개 테스트 통과. 새 문서 형식을 거부하는 테스트를 먼저 확인한 뒤 허용·검증 경로를 추가했다.
- 한국어 정적 화면: 참여자 전사, 보완 입력, 미리보기와 고정 적용 버튼, 별도 모델 선택 검증 통과.
- Worker `01eca5e1-6a62-470e-ae32-67db50d1b188` 배포 완료. `/v1/health`, AI 설정, 녹음 목록, 회의 분석 목록의 인증된 읽기 요청이 200을 반환했다.
- 실제 유료 AI 보완이나 전사 요청은 실행하지 않았다. 모델 출력의 사실관계는 미리보기에서 확인한 후 적용해야 한다.

로컬 로그는 `build/meeting-intelligence/`, 화면은 `build/visual-qa/`에 보관한다.

Mac·iPhone 1.4.0 (12) Release 빌드 및 서명 검증 후 두 기기에 설치했다. Mac은 최종 바이너리 일치와 실행을 확인했으며 이전 앱과 라이브러리는 `~/Library/Application Support/NoteTaker Backups/`에 보관했다. 개인 설치용 IPA는 `build/releases/AI-NoteTaker-iOS-1.4.0-build12.ipa`에 있으며 공개 저장소에는 포함하지 않는다.

iPhone에서도 설치된 버전과 실행을 확인했다 (`ios-installed-140.json`, `ios-launch-140.json`). 사용자의 기존 회의를 자동으로 다시 전사하거나 유료 보완하지 않았다.
