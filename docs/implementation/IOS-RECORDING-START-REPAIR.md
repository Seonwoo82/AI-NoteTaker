# iPhone 녹음 시작 직후 종료 수정 — 2026-09-16

## 실물 재현과 원인

등록된 내 목소리 프로필이 있으면 iPhone 녹음은 실시간 음성 샘플을 전달하는 `ObservedVoiceRecordingSession` 경로를 사용합니다. 이 경로가 모든 오디오 경로 변경 알림을 중단으로 처리해, 녹음 준비의 `categoryChange` 알림만으로도 녹음이 끝났습니다.

사용자 iPhone 15 Pro에서 기존 코드로 재현한 결과, 시작 상태는 정상으로 바뀌었지만 0.789초 내 종료됐고 입력 샘플은 0개였습니다. `route:3` 알림 두 번과 녹음 항목 한 개의 저장을 확인했습니다. 실제 문제 파일도 각각 557바이트였고, 경과 시간 약 0.226초를 오디오 길이로 대신 저장하고 있었습니다.

## 수정

- 정상적인 입력·형식·실행 상태에서는 시작 시 발생하는 경로/구성 알림을 무시합니다. 실제 입력 손실·변경, 형식 불일치, 실행 중인 엔진의 정지와 전화 수신 같은 중단은 계속 처리합니다.
- 일시 정지와 종료를 실제 장애로 오인하지 않으며, 종료·실패 시 알림 감시를 해제하고 오디오 세션을 정리합니다.
- 녹음 프레임이 없으면 경과 시간을 녹음 길이로 만들지 않습니다. 0·음수·NaN·무한대 길이는 저장하지 않고, 오류 복구도 실제 디코딩 가능한 프레임이 있을 때만 허용합니다. 정상적인 부분 녹음의 재저장은 유지합니다.
- 이전 녹음의 늦은 콜백이 새 녹음을 종료하지 못하도록 녹음 ID를 확인합니다. 시작 요청의 중복 진입도 차단합니다.
- 재생기는 자신이 활성화한 오디오 세션만 해제하고, 정지한 플레이어의 식별자·델리게이트를 해제해 늦은 콜백이 녹음을 방해하지 않도록 합니다.

주요 변경 파일은 `ObservedVoiceRecordingSession.swift`, `VoiceRecorder.swift`, `VoicePlayer.swift`, `LibraryAppModel.swift`이며 모두 iOS 앱 범위입니다.

## 검증

- 같은 실물 iPhone에서 수정 후 6.2초 동안 녹음 유지, 297,600개 실제 입력 샘플과 재생 가능한 파일 저장 확인. 정상 시작 알림 `route:3`이 있어도 종료되지 않았습니다.
- iPhone 시뮬레이터 전체 테스트: 421개 통과, 0개 실패, 선택적 모델/실기기 테스트 6개 제외.
- 별도 회귀 테스트에서 빈 파일·잘못된 길이·정상 부분 녹음 복구·이전 콜백·재생 세션 소유권·일시 정지/재개 확인.
- 서명된 iOS 1.7.3(빌드 26)을 실제 iPhone에 설치하고 실행했습니다. 기존 오디오·회의록 19개 파일의 크기와 수정 시간이 유지됐습니다. 이전의 빈 녹음 항목은 임의로 삭제하지 않았습니다.

실기기 마이크 테스트는 명시적인 `NOTETAKER_RECORDING_HARDWARE_TEST=1` 설정에서만 실행되며, 임시 라이브러리를 사용하고 테스트 음성을 삭제합니다. 일반 테스트 실행에서는 마이크를 열지 않습니다. 실제 전화 수신·Bluetooth 탈착은 이번 실기기 검증에 포함하지 않았으며 관련 입력 변화 판단과 중단 경로는 단위 테스트와 코드 검토로 확인했습니다.
