# 긴 회의의 출력 토큰 한도

## 1.3.3 (빌드 11)

최종 회의록과 구조화된 회의 분석의 요청 한도를 최대 **131,072토큰**, 긴 전사문의 중간 요약을 최대 **32,768토큰**으로 높였다. Qwen3.8 Max (0902)의 기존 최종 요청은 8,192토큰이었으므로 16배다. 생성량을 강제로 늘리는 값이 아니라 모델이 추론과 답변에 사용할 수 있는 상한이다.

`MeetingCompletionBudget`을 Mac·iOS 회의록 서비스와 공유 회의 분석 서비스가 함께 사용한다. 모델의 전체 문맥 중 일부를 출력에 할당하고 전사문과 프롬프트 공간을 남긴다. 공개 모델 목록의 `top_provider.max_completion_tokens`를 읽어 모델이 알려준 출력 한도를 넘지 않는다. 이전에 저장한 모델 목록도 그대로 읽을 수 있으며, AI 설정의 모델 목록 새로 고침으로 최신 제공자 한도를 가져온다. 한도가 제공되지 않으면 알려진 문맥 크기를 기준으로 계산한다.

길어진 추론·답변을 수신할 수 있도록 요청 대기 시간을 출력 예산에 비례해 3분~최대 60분으로 조정하고 세션 전체 제한도 그보다 길게 맞췄다. 모델·제공자 자체 시간 제한, 네트워크 상태, iPhone의 백그라운드 실행 제약은 별도다. 실제 생성된 토큰이 늘면 비용과 소요 시간도 늘 수 있다.

기존 전사문 캐시와 실패 시 재생성 경로를 유지한다. 길이 제한으로 잘린 응답은 완성된 회의록으로 저장하지 않으며, 유료 요청을 자동으로 반복하지 않는다. 기존 녹음에서 **다시 생성**하면 보존된 전사문을 재사용할 수 있다.

## 검증

- 기존 8,192 / 12,288토큰과 180초 제한으로 실패하는 회귀 테스트를 먼저 확인했다 (`output-budget-red.log`).
- 75분 녹음과 긴 한국어 전사문을 가정해 중간 요약·최종 합성 요청의 예산, 전사문 끝부분 보존, 결과 저장을 확인한다.
- 제공자 출력 상한, 작은 문맥의 입력 공간, 이전 모델 캐시 호환성, 구조화된 회의 분석의 예산도 검증한다.
- 테스트는 가짜 모델 응답을 사용한다. 사용자의 기존 회의를 OpenRouter로 다시 전송하거나 유료 재생성하지 않았다.

최종 검증 결과: Mac 375개, iOS 시뮬레이터 251개 테스트 통과. 양쪽 Release 빌드와 코드서명 검증 통과. Mac·iPhone 1.3.3 (11) 설치, Mac 실행 확인. iPhone은 잠금 상태여서 실행 요청이 거부됐다. 로그는 `build/meeting-intelligence/output-budget-*.log`에 보관한다. 실제 Qwen 유료 생성은 수행하지 않았으므로 길이 제한이 모든 회의에서 사라진다고 보장하지 않는다.
