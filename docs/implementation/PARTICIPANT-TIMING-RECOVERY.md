# 참여자 전사 시간 정보 복구 — 1.5.2 (빌드 16)

## 확인한 원인

상세 전사 응답의 단어 시작·종료 시간이 같은 경우를 OpenRouter 응답 파서는 허용하지만, 발화 조립기는 양의 길이만 허용하여 최종 참여자 전사 저장이 실패했다. 이 예외는 일반 회의록 저장 오류로 바뀌어 실제 원인이 화면에 드러나지 않았다. 녹음 끝보다 긴 제공자 구간도 실패를 일으킬 수 있었다.

시간 값만 같은 합성 회귀 사례에서 변경 전 실패를 재현했다. 실제 캐시 두 개에서도 길이 0인 단어가 확인되었다. 개인 녹음·전사문·경로는 이 문서나 저장소에 포함하지 않는다.

## 수정

- 길이 0인 단어의 텍스트는 인접한 유효 구간과 함께 보존한다. 시간 정보가 불명확한 텍스트에는 임의의 화자를 지정하지 않는다.
- 단어 시간이 모두 길이 0인 경우 제공자가 반환한 유효한 구간 시간을 사용한다.
- 구간 끝의 패딩만 실제 청크·녹음 끝으로 제한한다. 녹음 밖에서 시작하는 잘못된 시간은 여전히 거부한다.
- 원래 회의록과 기본 전사문, 선택 모델을 유지하며 참여자 전사만 보완한다.
- 참여자 작업의 실제 준비·전사 구간 수·로컬 화자 구분 상태를 표시한다. 이전 실패 안내는 재시도 중 숨긴다.
- 알려진 시간 검증·네트워크·HTTP 오류에는 해당 원인 안내를 표시한다. 임의의 제공자 오류 본문이나 API 키는 노출하지 않는다.

공유 `TranscriptAssembler.swift`를 고쳐 두 플랫폼에 적용한다. `MeetingAnalysisService.swift`의 구조화된 진행 상태를 양쪽 `MeetingNotesView`에 전달하고, `MeetingNotesService`의 참여자 전용 오류 처리를 보완한다. 새로운 의존성은 없다.

## 검증

- 길이 0인 중간·마지막 단어, 단어 대신 유효 구간 복구, 끝 패딩 처리의 실패 테스트를 먼저 확인했다.
- `LocalParticipantRecoveryTests`는 명시적 로컬 실행 파일이 있을 때만 실행한다. 임시 라이브러리와 기존 모델만 사용하며, 모든 네트워크 클라이언트 호출을 오류로 처리한다.
- 실제 실패 캐시 두 개를 이 진단으로 복구하고, 유효한 참여자 전사 저장과 기존 회의록·원본 전사 보존을 확인했다. 네트워크 호출은 0회였다.
- 짧거나 겹치는 발화의 참여자 번호는 자동 추정이다. 일부 짧은 발화가 별도 화자로 나뉘었으며, 복구 성공이 화자 인식 정확도 100%를 뜻하지 않는다.

## 반영 결과

- Mac 441개, iOS 310개 테스트 통과. 양쪽 Release 빌드 및 코드서명 검증 완료.
- 독립 코드 검토에서 추가 수정 사항 없음.
- Mac 1.5.2 (16) 설치 전에 앱과 라이브러리를 백업했다. 복구 대상의 원본 회의록 해시와 오디오 버전을 확인한 후, 검증된 참여자 문서만 원자적으로 반영했다. 원본 Markdown·기본 전사·모델·비용·보완 내용은 유지했다.
- 실제 설치 앱에서 참여자 번호 표시, 빈 참여자 안내 및 이전 실패 메시지 제거를 확인했다. 복구된 두 회의록의 Cloudflare 완료 문서 버전도 확인했다. 추가 OpenRouter 요청 없이 처리했다.
- iPhone Release와 로컬 IPA는 준비했으나 기기가 연결 불가 상태여서 설치되지 않았다. 기존 1.5.1 앱은 유지한다.
